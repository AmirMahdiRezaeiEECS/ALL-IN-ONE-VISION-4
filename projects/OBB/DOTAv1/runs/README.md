# Runs  
This directory contains **experiment outputs generated by Ultralytics**.  
The runs/ directory is intentionally kept as the native output layer of Ultralytics. This template does not introduce a separate artifact, checkpoint, logging, or experiment-management system around it.

## Purpose  
Ultralytics automatically creates run directories for operations such as:  
* Training  
* Validation  
* Prediction  
* Export  
* Other supported Ultralytics modes  
For example:  
```
runs/
└── detect/
    ├── train/
    ├── train2/
    ├── val/
    └── predict/

```
The exact contents depend on the task, mode, and options used.  
## Run Naming  
Ultralytics organizes outputs using a combination of project and name.  
For example:  
```
model.train(
    data="configs/datasets/dataset.yaml",
    project="runs/detect",
    name="baseline",
)

```
produces:  
```
runs/
└── detect/
    └── baseline/

```
The name parameter identifies an individual run.  
If a run directory already exists, Ultralytics normally creates an incremented directory rather than overwriting the existing run. This behavior can be changed with exist_ok=True.

## Training Outputs  
A typical training run may contain:  
```
runs/
└── detect/
    └── baseline/
        ├── weights/
        │   ├── best.pt
        │   └── last.pt
        │
        ├── args.yaml
        ├── results.csv
        ├── results.png
        ├── confusion_matrix.png
        ├── confusion_matrix_normalized.png
        ├── F1_curve.png
        ├── P_curve.png
        ├── PR_curve.png
        ├── R_curve.png
        └── ...

```
Important outputs include:  

| Output | Description |
| --------------------- | -------------------------------------------------------- |
| weights/best.pt | Best model checkpoint from the training run |
| weights/last.pt | Final checkpoint from the training run |
| args.yaml | Arguments/configuration used for the run |
| results.csv | Training and validation metrics recorded during training |
| results.png | Plots generated from the training results |
| confusion_matrix*.png | Confusion-matrix visualizations |
| *_curve.png | Precision, recall, F1, and related curves |
  
The exact files vary depending on the task and configuration.  
## Validation Outputs  
Validation also uses an Ultralytics run directory:  
```
runs/
└── detect/
    └── val/
        ├── confusion_matrix.png
        ├── confusion_matrix_normalized.png
        ├── F1_curve.png
        ├── P_curve.png
        ├── PR_curve.png
        ├── R_curve.png
        └── ...

```
Validation can generate metrics, plots, confusion matrices, and optionally JSON evaluation results.  
For example:  
```
metrics = model.val(
    data="configs/datasets/dataset.yaml",
    plots=True,
    save_json=True,
)

```
## Prediction Outputs  
Prediction results are also saved under runs/.  
For example:  
```
runs/
└── detect/
    └── predict/
        ├── image1.jpg
        ├── image2.jpg
        └── ...

```
The exact outputs depend on the prediction options and source type.  
## Controlling the Output Location  
Ultralytics provides three relevant parameters:  
```
project

```
Defines the parent directory:  
```
project="runs/detect"
name
```
```


```
Defines the individual run:  
```
name="baseline"

```
Together:  
```
runs/detect/baseline/
save_dir

```
Can be used when an exact output directory is required:  
```
save_dir="runs/detect/baseline"

```
save_dir takes precedence over the project + name combination.  
## Recommended Usage in This Template  
Keep experiment outputs inside runs/ and let **Ultralytics manage their internal structure**.  
For example:  
```
A4-project/
├── configs/
├── datasets/
├── notebooks/
├── runs/
│   └── detect/
│       ├── baseline/
│       ├── augmentation-v1/
│       └── larger-model/
├── README.md
└── pyproject.toml

```
The notebooks define and launch experiments:  
```
notebooks/
    ↓
Ultralytics
    ↓
runs/

```
Do not create additional directories such as:  
```
artifacts/
checkpoints/
logs/
metrics/
outputs/

```
solely to duplicate information already produced by Ultralytics.  
## Git  
Run outputs are generally **generated artifacts**, not source code.  
The repository should normally ignore the contents of runs/ while preserving the directory itself:  
```
runs/*
!runs/.gitkeep

```
This keeps the template structure available without committing potentially large checkpoints, images, metrics, and other generated files.  
## Principle  
**The project defines the experiment; Ultralytics owns the run.**  
This directory exists to provide a consistent location for Ultralytics-generated outputs while avoiding unnecessary custom experiment-management infrastructure.
